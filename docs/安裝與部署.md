# 安裝與部署

適用版本：v1.0.0。以下以 Windows x64、預設 Ollama 後端及本機控制台為主。

## 1. 安裝前準備

| 元件 | 準備方式 |
| --- | --- |
| 系統 | Windows x64，專案資料夾需可寫入 |
| Python | bootstrap 準備 Python 3.12 與專案虛擬環境 |
| 本機模型 | 自行準備可使用的 Ollama 模型，名稱與設定一致 |
| LibreOffice | 安裝 Windows 版本，用於 PPTX → PDF 及頁面預覽 |
| GPU、RAM、磁碟 | 依模型和上下文需求準備，另留成果與快取空間 |
| 網路 | 首次環境下載、模型準備及選用的線上圖片搜尋 |

發布包包含程式、預設規則、品牌素材、文件與安裝介面。模型權重、教材庫、已有教材和訓練環境需另外準備。

## 2. 從 Release 安裝

1. 開啟 [正式版本列表](https://github.com/welwang/teaching-ai/releases)。
2. 下載 `TeachingAI-Installer-v1.0.0.zip` 與同名 `.sha256`。
3. 在 PowerShell 計算校驗值，與 `.sha256` 第一欄比對：

```powershell
Get-FileHash .\TeachingAI-Installer-v1.0.0.zip -Algorithm SHA256
```

4. 解壓縮整個安裝包，保留目錄結構。
5. 雙擊 `installer/Install-TeachingAI.cmd`，選擇一個專用安裝資料夾。
6. 安裝目標需與解壓縮資料夾分開；安裝程式會拒絕磁碟根目錄、重疊路徑和連結目錄。
7. 到安裝資料夾執行 `Start-TeachingAI.cmd`。

安裝介面先複製程式檔案。第一次啟動才準備執行環境，所需時間取決於下載與主機狀況。模型和轉檔工具需依下列步驟驗證。

## 3. 從原始碼安裝

```powershell
git clone https://github.com/welwang/teaching-ai.git
cd teaching-ai
Copy-Item config.example.yaml config.yaml
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 -NoLaunch
```

如果已建立 `config.yaml`，保留原設定即可。bootstrap 只在設定檔不存在時複製範本。

環境準備完成後：

```powershell
.\Start-TeachingAI.cmd
```

控制台預設網址為 `http://127.0.0.1:8502/`。專案不需要先安裝 Docker 或 WSL。

## 4. Python 與依賴

bootstrap 會確認 `.venv/Scripts/python.exe` 可用且為 Python 3.12 虛擬環境，必要時準備官方 Python 並安裝 `requirements.txt`。不可用的環境會保留為恢復用目錄，再建立新環境。

核心依賴包括 Streamlit、requests、PyYAML、jsonschema、python-pptx、python-docx、PyMuPDF、Pillow、filelock、psutil 與 Playwright。確切版本以 [`requirements.txt`](../requirements.txt) 為準。

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -c "import streamlit, requests, yaml, jsonschema, pptx, docx, pymupdf, PIL, filelock, psutil"
```

如果機器已有受管理的 Python 3.12，也可自行建立隔離環境後安裝依賴；仍需確認模型與 LibreOffice。

## 5. 準備本機模型

### 5.1 專案模型服務

Ollama 預設服務位址為 `127.0.0.1:11435`，專案自行啟動的服務將權重放在 `models/ollama/`。一般 Ollama 的預設服務與模型目錄，可能與此專案不同。

如果先做模型設定，可在環境安裝完成後啟動專案引擎：

```powershell
.\.venv\Scripts\python.exe -m workflow_v2.engine 1
Invoke-RestMethod http://127.0.0.1:11435/api/tags
```

這只啟動引擎，不會提供指定模型的權重。

### 5.2 確認 CLI 指向同一服務

以下選擇已安裝的 Ollama 執行檔，並列出專案服務中的模型：

```powershell
$ollamaExe = Join-Path $PWD 'runtime\ollama\ollama.exe'
if (-not (Test-Path -LiteralPath $ollamaExe)) {
    $installedOllama = Join-Path $env:LOCALAPPDATA 'Programs\Ollama\ollama.exe'
    if (Test-Path -LiteralPath $installedOllama) {
        $ollamaExe = $installedOllama
    } else {
        $ollamaExe = (Get-Command ollama -ErrorAction Stop).Source
    }
}
$env:OLLAMA_HOST = '127.0.0.1:11435'
& $ollamaExe list
```

需要下載或匯入模型時，沿用這個服務位址。若 `11435` 的列表為空，而另一個 Ollama 有模型，不表示本專案已能使用它。

### 5.3 設定實際模型名稱

預設 `preferred_model` 為 `qwen3.8:27b-q4_K_M`。這是本機設定標籤，部署時需匯入已有權重，或依實際部署修改設定中的名稱。

例如，若已匯入的名稱為 `teaching-local`：

```yaml
preferred_model: teaching-local
model_selection: fixed
generation_context: 32768
```

選用其他模型時，需要重新驗證結構化 JSON、教學品質、記憶體需求及掃描教材所需的影像能力。一般使用者在製作頁不選模型；模型政策由設定檔管理。

## 6. LibreOffice 與預覽

安裝 LibreOffice Windows 版本。`office.py` 會依序查找專案的 `runtime/libreoffice/program/soffice.com`、系統 Program Files 中的安裝與 PATH。

流程為 PPTX → LibreOffice PDF → PyMuPDF PNG。缺少 LibreOffice 會讓預覽階段失敗；產生中間 PPTX 不代表整個發布流程完成。

安裝後使用「系統與紀錄 → 開始檢查」，或執行：

```powershell
.\.venv\Scripts\python.exe -m workflow_v2.health
```

此指令會實際檢查資料庫、模型、GPU、磁碟、瀏覽器與轉檔；報告保存於 `data/workflow-v2/health.json`。

## 7. 設定欄位

| 欄位 | 預設 / 限制 | 使用方式 |
| --- | --- | --- |
| `ollama_url` | 本機 HTTP，預設 `11435` | 模型請求與服務檢查 |
| `preferred_model` | 已安裝模型的完整名稱 | 基礎模型 |
| `distilled_model` | 可省略或留空 | 經比較後採用的文字蒸餾模型 |
| `generation_architecture` | 預設 `dense_27b` | 後端架構設定 |
| `model_selection` | 預設 `fixed` | 按系統設定綁定工作模型 |
| `generation_context` | 8192、16384、32768 | 固定上下文上限 |
| `ollama_parallel` | 預設 1 | 模型服務槽位數 |
| `write_concurrency` | 預設 1 | 編寫頁面並行數 |
| `parallel_min_total_vram_mb` | 範本 28000 | 並行判定條件 |
| `parallel_min_free_vram_mb` | 範本 20000 | 並行判定條件 |
| `console_refresh_seconds` | 1～60，預設 1 | 監控刷新間隔 |
| `image_generation_enabled` | 預設 `false` | 開啟本機生圖 |
| `image_generation_url` | 本機 SD WebUI 相容端點 | 插圖生成 API |
| `image_generation_python` | 啟用自動啟動時設定 | 生圖服務 Python 路徑 |
| `image_generation_launcher` | 啟用自動啟動時設定 | 生圖服務啟動程式 |
| `image_priority_unload_resident_models` | 預設 `true` | 生圖前協調顯存 |
| `slide_logo` | `off` 或 `cover` | 是否在簡報封面加入小標誌 |

修改設定後重新開啟程式。只有管理員設定模型政策，任務層選項則在製作頁調整。

## 8. 圖片與可選元件

預設安裝包關閉本機生圖。任務仍可選擇線上開放授權圖片，或使用程式產生的原生圖解與文字版面。

如果已有 Forge 或 SD WebUI 相容服務，再依其實際安裝位置設定生圖路徑。目前端點驗證以本機服務為主。

Strata 後端和蒸餾訓練屬於進階配置；一般控制台安裝不需要先建立訓練環境。參閱 [Strata 說明](../STRATA-整合說明.md)與 [蒸餾工具](../distill/README.md)。

## 9. 首次使用驗收

1. 確認控制台能開啟，三個分頁和五種配色可操作。
2. 確認模型列表含設定名稱，LibreOffice 檢查可匯出 PDF。
3. 使用有權使用、篇幅較短的 TXT、Markdown 或文字型 PDF。
4. 選擇「上傳檔案」、填單元名稱，製作 8 頁測試教材。
5. 追蹤七個階段，下載 PPTX、PDF 與教師備課稿。
6. 查看來源頁碼、品質警示、預覽與製作時間，再測試單頁編輯。

每台新主機需完成實際生成驗收。專案不以固定秒數承諾整份教材的速度或正確性。

## 10. 更新與備份

更新前先停止生成服務，保存 `config.yaml`、`data/` 和模型配置。Git 使用者可在工作區乾淨時更新：

```powershell
git pull --ff-only
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 -NoLaunch
.\Start-TeachingAI.cmd
```

安裝包使用者下載新版，先解壓縮到新資料夾，對照設定範本並備份資料，再按部署需求替換程式。

備份至少包含 `config.yaml`、完整 `data/workflow-v2/`、來源上傳檔與需要的模型配置。資料庫仍在寫入時不宜只複製單一 `.sqlite` 而忽略 WAL；先停止工作程序，再備份完整資料目錄。

## 11. 排錯

| 現象 | 檢查方向 |
| --- | --- |
| 控制台無法開啟 | 查看 `logs/web-v2.err.log`、Python 環境與 `8502` 埠占用 |
| 找不到指定模型 | 查 `11435/api/tags`，確認模型名稱和服務一致 |
| 模型服務未啟動 | 查 `logs/ollama.err.log`、引擎安裝與程序所有權 |
| 顯存不足 | 停用頁面並行，檢查模型、上下文和其他 GPU 程式 |
| PDF 預覽失敗 | 確認 LibreOffice 安裝，執行服務檢查，再從失敗處重試 |
| 教材庫沒有單元 | 新安裝不附教材庫，切換「上傳檔案」 |
| 掃描 PDF 文字錯誤 | 確認模型影像能力，查辨識診斷或改用可讀文字來源 |
| 插圖無法產生 | 檢查生圖開關與服務；查看 `visual-assets.json` 的缺圖原因 |
| 需要教師補寫 | 查看頁碼、失敗原因與品質報告，編輯或重製該頁 |
| 已暫停但目前階段仍執行 | 確認操作的是「暫停佇列」還是「暫停單一任務」 |

回報問題時附上版本、模型、失敗階段和最小重現資料；完整教材與修改歷史可留在部署機。
